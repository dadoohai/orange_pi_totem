# C21.22 Wi-Fi state and recovery board E2E

## Claim

C21.22 is a homologation-only `totem-core` candidate that closes M9 items 4
through 6:

- truthful visual states for Wi-Fi list, cache, refresh, connection, success,
  failure and recovery;
- explicit distinction between Ethernet, associated Wi-Fi and access to the
  Dadooh service;
- safe failure categories with direct retry and retained context.

It is not a stable promotion, public release, captive-portal implementation or
new reference image.

## Behavior Implemented

- Empty, cached, refreshing and unavailable Wi-Fi list states are distinct.
- Online, limited, offline and unknown are distinct public connectivity states.
- The product describes Dadooh service access, not generic internet access.
- A probe observed through one transport is not attributed to another
  transport.
- Authentication, timeout, unavailable network, weak signal, missing IPv4,
  unavailable device and generic activation failures have sanitized copy.
- Non-authentication retries preserve the selected network and password
  context; authentication failures reopen correction.
- Public artifacts do not expose SSID, password, IP, MAC, DNS or raw logs.

## Honest Limits

- Captive portal detection and a temporary browser remain M9 items 7 and 8.
- Physical association with an open AP remains pending from C21.21.
- This run did not inject real Wi-Fi failures or replace the current network.
- The interactive framebuffer probe was not run because its safety preflight
  found a private homologation seed. Visual evidence is the reviewed off-board
  gallery plus preview screens generated by the installed package on the board.
- The package was applied locally under a temporary homologation policy. It was
  not published or consumed by the public stable timer.
